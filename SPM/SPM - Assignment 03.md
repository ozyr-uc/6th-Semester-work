# Part A — Requirements & Quality Plan

# 1. Functional Requirements

| ID   | Functional Requirement                                            |
| ---- | ----------------------------------------------------------------- |
| FR-1 | Students shall be able to upload assignments through the system.  |
| FR-2 | Teachers shall be able to review and grade submitted assignments. |
| FR-3 | The system shall send deadline notifications to students.         |

---

# 2. Non-Functional Requirements

| ID    | Non-Functional Requirement                                          |
| ----- | ------------------------------------------------------------------- |
| NFR-1 | The system should be available 99% of the time.                     |
| NFR-2 | The system response time should not exceed 3 seconds.               |
| NFR-3 | User data must be protected using secure authentication mechanisms. |

---

# 3. Quality Objectives

| Quality Objective | Description                                                     |
| ----------------- | --------------------------------------------------------------- |
| Reliability       | Ensure stable and error-free assignment submission and grading. |
| Security          | Protect user data and prevent unauthorized system access.       |

---

# 4. Quality Metrics

# 2. Procurement Decisions

## Outsourced Items
- Cloud hosting
- Domain registration
- UI templates

These are outsourced because external providers offer reliable and cost-effective solutions.

## In-House Items
- System design
- Backend development
- Database logic
- Testing

These are kept in-house because they are core parts of the project.

# 3. Suitable Contract Type

## Fixed Price Contract

A fixed price contract is suitable because:
- Project requirements are mostly predefined
- Budget control becomes easier
- Cost risks are reduced
- Small academic projects require predictable expenses
